# Google Apps Script 버전 (PC 안 켜도 되는 방법)

같은 감시를 **구글 서버에서** 돌립니다. 내 컴퓨터는 꺼져 있어도 됩니다.

|  | Apps Script (이 폴더) | Python (`wedding_watch/`) |
|---|---|---|
| 돌아가는 곳 | 구글 서버 | 내 PC 또는 내 서버 |
| PC 켜둬야 하나 | **아니오** | 예 |
| 설치 | 복사·붙여넣기 10분 | 파이썬 설치 필요 |
| 비용 | 무료 | 무료 |

**확인된 사실** (2026-09 실제 실행 기준): 구글 서버 IP에서 사이트 조회가 **정상 동작**하며,
**로그인도 필요 없습니다.** 달력 응답에 `days.{일}.closed` 가 그대로 들어옵니다.

## 알림 채널 — 이메일은 기본, 나머지는 선택

**설정을 하나도 안 해도 내 구글 계정 이메일로 알림이 옵니다.** 그 위에 더 빠른 채널을 얹는 구조입니다.

| 순서 | 채널 | 설정 | 특징 |
|---|---|---|---|
| 1 | **텔레그램** | 5분 | 즉시 푸시, 무료, 제한 없음 — **권장** |
| 2 | **ntfy** | 2분 | 즉시 푸시지만 **자주 막힙니다** (아래 참고) |
| 3 | **이메일** | **0분** | 항상 동작하는 마지막 보루 |

위에서부터 시도하고 **하나라도 성공하면 멈춥니다.** 텔레그램이 죽으면 ntfy로, 그것도 막히면
이메일로 내려갑니다. 채널 하나가 막혀서 빈자리를 놓치는 일이 없게 하려는 구조입니다.

> ### ⚠️ ntfy 를 단독으로 쓰면 안 되는 이유
>
> ntfy.sh 무료는 **하루 250통 제한을 IP 주소 기준**으로 셉니다. 그런데 Apps Script는
> **구글의 공용 IP**로 나가기 때문에, 전 세계 수많은 사람과 **같은 할당량을 나눠 씁니다.**
> 내가 한 통도 안 보냈는데 `429 daily message quota reached` 가 뜨는 이유입니다.
>
> **ntfy 계정을 만들어 토큰을 넣어도 무료 티어는 여전히 IP 기준**이라 해결되지 않습니다
> ([ntfy 이슈 #1726](https://github.com/binwiederhier/ntfy/issues/1726),
> [#1963](https://github.com/binwiederhier/ntfy/issues/1963)).
>
> 그래서 이 스크립트는 ntfy를 **쓰되 믿지는 않습니다.**

## 설치

### 1. 스크립트 만들기

1. [script.google.com](https://script.google.com) 접속 → **새 프로젝트**
2. 왼쪽 위 프로젝트 이름을 `웨딩홀 빈자리 알림` 등으로 변경
3. 편집기의 기본 코드를 **전부 지우고**, [`Code.gs`](Code.gs) 내용을 **전부 복사해 붙여넣기**
   ([붙여넣기용 링크](https://raw.githubusercontent.com/hayaart/basic/claude/google-scripts-notification-review-a53nx5/apps-script/Code.gs))
4. 💾 저장 (Ctrl+S / Cmd+S)

### 2. 알림 채널 정하기

설정은 전부 **⚙️ 프로젝트 설정 → 맨 아래 스크립트 속성**에서 합니다.

**(a) 이메일만 쓸 거라면 — 아무것도 안 해도 됩니다.** 내 구글 계정으로 옵니다.
다른 주소로 받고 싶을 때만:

| 속성 | 값 |
|---|---|
| `EMAIL_TO` | 받을 이메일 주소 |

**(b) 텔레그램 (권장)**

1. 텔레그램에서 **`@BotFather`** 를 검색해 대화를 엽니다
2. `/newbot` 을 보내고, 시키는 대로 봇 이름을 정합니다
3. BotFather가 주는 **토큰**(`1234567890:AAE...` 모양)을 복사합니다
4. 스크립트 속성에 `TELEGRAM_TOKEN` 으로 저장
5. 텔레그램에서 **방금 만든 내 봇에게 아무 말이나** 한 마디 보냅니다 (`안녕` 등)
6. Apps Script 편집기에서 **`findTelegramChatId`** 함수를 실행하면 로그에 숫자가 나옵니다
7. 그 숫자를 스크립트 속성에 `TELEGRAM_CHAT_ID` 로 저장

**(c) ntfy (선택)**

| 속성 | 값 |
|---|---|
| `NTFY_TOPIC` | 폰 ntfy 앱에서 구독한 토픽 이름 |
| `NTFY_TOKEN` | (선택) ntfy 계정 토큰 |
| `NTFY_SERVER` | (선택) 자체 호스팅 서버 주소 |

> 🔒 ntfy 토픽은 **이름만 알면 누구나 구독(내 알림 엿보기)하고 발행(가짜 알림)** 할 수 있습니다.
> 남이 본 적 있는 이름은 버리고 새로 만드세요.

### 2-1. 다른 예식장 / 다른 달을 보고 싶다면 (선택)

**자동 감시는 한 곳만** 합니다. 기본값은 **삼성금융연수원(코드 5)** 이고,
**예약을 받는 달을 스스로 찾아 전부 감시**합니다.
다른 예식장은 감시하지 않고, [텔레그램에서 이름을 불러](#-텔레그램에서-말-걸어-확인하기-선택) 그때만 찾아봅니다.
코드를 고치지 않고 **스크립트 속성**으로 바꿀 수 있습니다.

| 속성 | 값 | 안 넣으면 |
|---|---|---|
| `HALL_CODE` | 감시할 예식장 코드 | `5` (삼성금융연수원) |
| `HALL_NAME` | 알림에 쓸 이름 | `삼성금융연수원` |
| `MONTHS` | `2027-05, 2027-06` 처럼 쉼표로 구분 | **열린 달 전부 자동** |
| `MAX_MONTHS_AHEAD` | 자동 탐색 시 몇 달 앞까지 볼지 | `24` |

**자동 탐색이 하는 일**: 이번 달부터 한 달씩 앞으로 가면서 조회하다가, 예약을 아예 안 받는
(날짜 목록이 비어 있는) 달이 **3번 연속** 나오면 거기가 끝이라고 보고 멈춥니다.
사이트가 새로운 달을 열면 **설정을 안 고쳐도 10분 안에 감시 대상에 들어옵니다.**

> 조회 실패는 '빈 달'로 치지 않습니다. 중간에 한 달이 실패해도 멈추지 않고 끝까지 훑습니다.

> ⏱️ 자동 탐색은 한 번 돌 때 **열린 달 수 + 3번** 사이트를 조회합니다 (보통 15~20회).
> 10분 주기면 하루 3천 회 정도로, 구글 일일 한도(2만) 안에 넉넉히 들어옵니다.
> 확인 주기를 1~5분으로 줄이고 싶다면 `MONTHS` 로 달을 좁히세요.

**알려진 예식장 코드** (실제 확인됨):

| 코드 | 예식장 |
|---|---|
| `1` | 서초사옥 |
| `3` | 삼성E&A |
| `5` | 삼성금융연수원 (기본값) |

**목록에 없는 예식장이라면** 편집기에서 **`findHallCodes`** 를 실행하세요.
1~15번을 한 달치씩 훑어서 이렇게 찍어줍니다.

```
2027-05 기준으로 예식장 코드 1~15 를 훑어봅니다. (현재 설정: 5 = 삼성금융연수원)
코드 1 → 조회된 날 10개 / 열린 날 0개
코드 2 → 조회된 날 9개 / 열린 날 3개: 2027-05-08, 2027-05-15, 2027-05-22
코드 5 → 조회된 날 10개 / 열린 날 0개
...
```

**열린 날이 있는 코드**가 찾는 예식장일 가능성이 큽니다. 이미 자리가 있는 걸 아는
예식장으로 맞춰보면 어느 번호인지 금방 가려집니다.

> 예식장을 바꾸면 이전 예식장에서 기억해 둔 날짜는 **자동으로 지워집니다.**
> (안 지우면 같은 날짜가 새 예식장에서 열려도 "이미 알린 날"로 취급돼 알림이 안 갑니다.)

### 3. 테스트

함수 선택 칸에서 **`sendTestPush`** 를 고르고 **▶ 실행**.

처음 실행하면 권한을 묻습니다 → *권한 검토* → 계정 선택 →
*"Google에서 확인하지 않은 앱"* → **고급** → **(프로젝트 이름)(으)로 이동** → **허용**.

> 이메일 발송 권한이 포함돼 있어서, 코드를 새로 붙여넣은 뒤에는 **권한을 다시 승인**해야 할 수 있습니다.

로그가 이런 모양이면 성공입니다:

```
설정된 알림 채널: 텔레그램 → ntfy → 이메일
알림 전송 성공
세션 쿠키 발급 성공
2027-05 원본 days: {"1":{"closed":true},"2":{"closed":true},...
2027-05 → 조회된 날 10개 중 열린 날: 없음(전부 마감)
```

| 로그 | 뜻 | 대응 |
|---|---|---|
| `모든 채널 전송 실패` | 채널 설정 오류 | 2단계 속성 이름·값 확인 |
| `앞 채널 실패 후 이메일로 보냈습니다` | 정상 (폴백 동작) | 그대로 두거나 텔레그램 설정 |
| `세션 쿠키 발급 실패` | 사이트가 막음 | [Python 버전](../README.md) 사용 |
| `응답이 JSON이 아님(차단 의심)` | 로그인 페이지가 돌아옴 | 위와 같음 |

### 4. 자동 실행 켜기

**`createTrigger`** 를 고르고 **▶ 실행**.
로그에 `10분마다 실행되는 트리거를 만들었습니다.` 가 나오면 끝입니다.

**첫 자동 실행 때는 지금 열려 있는 날짜를 한 번에 알려줍니다.** 그 다음부터는 새로 생긴 날짜만 알립니다.

## 🤖 봇 두 개로 나누기 (권장)

봇을 둘로 나누면 **알림 대화방이 조용해집니다.**

| 봇 | 무엇이 오나 | 얼마나 자주 |
|---|---|---|
| **알림 봇** | 🎉 빈자리 · ⚠️ 확인 실패 · ✅ 복구 | 거의 안 옴 — **오면 봐야 하는 것** |
| **상태 봇** | 📌 고정 상태 메시지 · 💓 하트비트 | 10분마다 조용히 갱신 |

이렇게 두면 **알림 봇에서 알림이 울리면 그건 진짜입니다.**

만드는 법은 첫 봇과 같습니다. `@BotFather` 에서 봇을 하나 더 만들고:

| 속성 | 값 |
|---|---|
| `STATUS_TELEGRAM_TOKEN` | 새 봇 토큰 |
| `STATUS_TELEGRAM_CHAT_ID` | **`findStatusTelegramChatId`** 실행해서 나온 숫자 |

두 속성을 **비워두면 알림 봇이 둘 다 겸합니다** (기존과 동일).

> ⚠️ 실패 알림(⚠️)은 **일부러 알림 봇으로** 보냅니다. 놓치면 안 되는 것이니까요.
> 상태 봇은 "조용히 지켜보는" 용도입니다.

## 📌 살아있는지 확인하기 — 텔레그램 고정 메시지

텔레그램을 쓰면, 봇 대화방에 **상태 메시지가 하나 생기고 10분마다 저절로 갱신**됩니다.

```
🟢 감시 중

예식장: 서초사옥
마지막 확인: 9월 22일 (화) 18:52
확인한 달: 15개
현재 빈자리: 없음

10분마다 이 메시지가 갱신됩니다. 시각이 안 바뀌면 멈춘 것입니다.
```

**이 메시지를 길게 눌러 `고정`(Pin) 해두세요.** 대화방 맨 위에 붙어 있어서, 열 때마다
마지막 확인 시각이 바로 보입니다. **시각이 계속 바뀌면 정상**입니다.

| 표시 | 뜻 |
|---|---|
| 🟢 감시 중 | 정상 |
| 🟡 일부만 확인됨 | 일부 달 조회 실패. 잠깐이면 괜찮습니다 |
| 🔴 감시 멈춤 | 확인이 안 되고 있습니다. 원인도 같이 적힙니다 |

> 갱신은 **기존 메시지를 고쳐 쓰는 것**이라 알림이 울리지 않습니다. 조용히 바뀌기만 합니다.
> 메시지를 실수로 지워도 다음 회차에 새로 만듭니다.

## 💬 텔레그램에서 말 걸어 확인하기 (선택)

봇에게 **"상태"** 라고 보내면 바로 답하게 할 수 있습니다. **"확인"** 이라고 보내면 그 자리에서 다시 조회합니다.

```
나:  상태
봇:  🟢 감시 중

     예식장: 삼성금융연수원
     마지막 성공: 3분 전 (9월 22일 18:52)
     현재 빈자리: 없음

     "확인" 이라고 보내면 지금 바로 다시 봅니다.
```

**감시하지 않는 예식장도 이름만 부르면 그 자리에서 찾아봅니다.**

```
나:  서초
봇:  🔎 서초사옥 을(를) 지금 찾아보고 있습니다. 20초쯤 걸립니다…
봇:  🎉 서초사옥 — 빈자리 24건
     확인한 달: 18개

     2027년 7월: 3(토), 4(일), 10(토), 11(일), 17(토), 18(일), 24(토), 25(일), 31(토)
     2027년 8월: 1(일), 7(토), 8(일), ...
```

### 버튼으로도 됩니다

답장과 고정 상태판에는 **버튼이 같이 붙어 옵니다.**

```
🟢 감시 중
예식장: 삼성금융연수원
...
┌──────────┬─────────┬──────────────┐
│ 서초사옥  │ 삼성E&A │ 삼성금융연수원 │
├──────────┴────┬────┴──────────────┤
│  🔄 상태       │   🔁 지금 확인     │
└───────────────┴───────────────────┘
```

**버튼을 누르는 것과 그 말을 직접 입력하는 것은 완전히 같습니다.** 같은 길로 처리됩니다.

| 보낼 말 | 하는 일 |
|---|---|
| `서초` | 서초사옥을 지금 찾아보기 |
| `금융` 또는 `연수원` | 삼성금융연수원을 지금 찾아보기 |
| `E&A` | 삼성E&A를 지금 찾아보기 |
| `확인` | **감시 대상**을 지금 다시 확인 (알림도 나감) |
| `상태` · 그 밖의 아무 말 | 기억해 둔 상태 바로 보기 (사이트 조회 안 함) |

> 이름을 불러 찾아보는 것은 **그 자리에서 보여주기만** 합니다. 알림을 보내거나
> 기억해 둔 상태를 바꾸지 않습니다. 그건 자동 감시 대상의 몫입니다.

고정 메시지만으로 충분하다면 이 단계는 건너뛰어도 됩니다.
**봇을 둘로 나눠 뒀다면 양쪽 다 답합니다** — 물어본 봇이 답합니다.

### 켜는 법

**1) 웹 앱으로 배포**

편집기 오른쪽 위 **배포 → 새 배포** → 왼쪽 **⚙️ 톱니 → 웹 앱** 선택 → 아래처럼 맞춥니다.

| 항목 | 값 |
|---|---|
| 실행 권한 | **나** |
| 액세스 권한 | **모든 사용자** |

**배포** 를 누르면 `https://script.google.com/macros/s/.../exec` 주소가 나옵니다. **복사하세요.**

> "모든 사용자"가 필요한 이유는 텔레그램 서버가 이 주소를 불러야 하기 때문입니다.
> 주소만 알면 누구나 부를 수 있으므로, 스크립트는 **주소 뒤에 붙는 비밀값과 대화방 번호가
> 모두 맞을 때만** 답합니다. 그 외에는 아무 반응도 하지 않습니다.

**2) 주소 등록**

⚙️ 프로젝트 설정 → 스크립트 속성 추가:

| 속성 | 값 |
|---|---|
| `WEBAPP_URL` | 복사한 `.../exec` 주소 |

**3) 켜기**

편집기에서 **`setupTelegramCommands`** ▶ 실행 →
`켰습니다. 텔레그램에서 봇에게 "상태" 라고 보내보세요.` 가 나오면 끝입니다.

### 끄는 법

**`removeTelegramCommands`** 실행.

> ⚠️ 이 기능이 켜져 있으면 `findTelegramChatId` 가 동작하지 않습니다 (텔레그램이 둘을 같이
> 못 쓰게 합니다). 채팅 ID 를 다시 찾아야 하면 `removeTelegramCommands` 를 먼저 실행하세요.

### 코드를 고친 뒤에는

웹 앱은 **배포된 시점의 코드**로 돕니다. 코드를 바꾸면
**배포 → 배포 관리 → ✏️ 수정 → 버전 `새 버전` → 배포** 를 해줘야 대화 기능에 반영됩니다.
(자동 감시는 배포와 무관하게 저장한 최신 코드로 돕니다.)

## 어떤 알림이 오나요

| 알림 | 언제 |
|---|---|
| 🎉 `삼성금융연수원 빈자리 N건` | 새 빈자리가 나왔을 때 |
| ⚠️ `확인 필요 — 삼성금융연수원 N건` | 빈자리로 보이지만 응답 형식이 바뀐 것 같을 때 (직접 확인하세요) |
| ⚠️ `빈자리 확인 실패 3회 연속` | 30분 넘게 **전체** 확인이 안 될 때 |
| ⚠️ `일부 달을 계속 못 보고 있습니다` | 특정 달만 2시간 넘게 안 될 때 (나머지는 정상 감시) |
| ✅ `감시 복구됨` | 위 문제가 해결됐을 때 |
| 💓 `삼성금융연수원 감시 중` | 하루 한 번, 살아있다는 신호 |

**⚠️ 알림이 왜 중요한가**: 알림이 안 오는 상태에는 두 가지가 있습니다 — *빈자리가 없어서* 와
*확인 자체가 망가져서*. 둘을 구분 못 하면 망가진 채로 몇 주가 지나갑니다.
그래서 이 스크립트는 **실패했다는 사실 자체를 알립니다.**

💓 하트비트가 성가시면 `Code.gs` 위쪽의 `HEARTBEAT_HOURS` 를 `0` 으로 바꾸세요.
다만 **구글이 트리거를 비활성화하면 실패 알림조차 못 오므로**, 켜 두는 쪽을 권합니다.

## 이 버전이 특별히 신경 쓴 것

| 상황 | 어떻게 처리하나 |
|---|---|
| 알림 채널 하나가 막힘 | 다음 채널로 자동 폴백. 이메일이 마지막 보루 |
| 일부 달만 조회 실패 | 실패한 달은 **이전 상태를 유지**. 상태가 날아가 같은 날짜를 다시 알리는 일을 막습니다 |
| 전체 조회 실패 | 상태를 **건드리지 않고** 실패만 기록. 3회 연속이면 점검 알림 |
| 응답 형식이 바뀐 듯함 | 알림을 **막지 않고** 제목을 바꿔 '직접 확인하라'고 알립니다 |
| 세션 쿠키 발급 실패 | 빈 쿠키로 계속 진행하지 않고 즉시 실패 처리 |
| 일시적 네트워크 오류 | 2초 쉬고 한 번 더. 한 회차에 20번 가까이 부르다 보면 하나쯤은 튕깁니다 |
| 한 달만 안 될 때 | 감시가 멈춘 것과 구분해서, 2시간 이어질 때만 알립니다 |
| 텔레그램 재전송 | 답이 늦으면 텔레그램이 같은 메시지를 또 보냅니다. 번호로 걸러 한 번만 답합니다 |
| 감시 대상 예식장 변경 | 이전 예식장의 기억을 지워, 같은 날짜라도 새로 알립니다 |
| 사이트가 새 달을 열었을 때 | 자동 탐색이 다음 회차에 바로 집어넣습니다 |
| 지나간 달 | 기억에서 자동으로 버립니다 |
| 실행이 겹침 | `LockService` 로 한 번에 하나만 |
| 규칙적인 접속 패턴 | 매 실행을 0~90초 무작위로 늦춤 |
| 한글·이모지 알림 제목 | ntfy 헤더 제약(latin-1) 때문에 RFC 2047 로 인코딩 |
